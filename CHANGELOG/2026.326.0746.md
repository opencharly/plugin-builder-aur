# 2026.326.0746 — refactor(builder)!: serve every `aur` leg through the one shared builder dispatch

## Summary

The `aur` builder plugin's half of the unified builder mechanism (opencharly/sdk#608). Before, each builder plugin carried its own copy of the three builder legs (`OpResolve`, `OpCollectContext`, `OpReverse`) — four byte-identical copies across the builder plugins. Now the plugin serves them through the ONE shared dispatch, `sdk.InvokeBuilder`, which is the same for every builder (R2).

- `plugin.go`'s `Invoke` delegates those three ops to `sdk.InvokeBuilder(builderWord, req)`. An op no builder serves is still refused.
- The stage template, the payload and (for aur) the package output come from `sdk/kit`, owned once for every builder.

**Dependencies.** `go.mod` moves two pins, and the rest of its diff follows from them:
- `github.com/opencharly/sdk v0.2026234.347` → `v0.2026326.342` (sdk#613, merged and tagged) and `github.com/opencharly/spec v0.2026232.520` → `v0.2026326.323` (spec#420, merged and tagged).
- The `go` directive goes `1.26.4` → `1.26.8` because `go get` raised it to the newer module's own directive; the tree builds and tests at that version.
- The new indirect `require` block (`cuelabs.dev/go/oci/ociregistry`, `opencontainers/go-digest`, `opencontainers/image-spec`, `rogpeppe/go-internal`, `x/oauth2`, `x/sync`) is the transitive closure of the new sdk: `go mod tidy` adds what sdk imports, and nothing in this repo imports them directly.
- The `grpc`, `x/net`, `x/sys`, `x/text`, `go-toml`, `yaml` bumps are that same tidy moving to the versions the new sdk requires.
- `go.sum` moves with `go.mod` and nothing else: it is the checksum record of exactly those modules, including the families the new sdk pulls in (`containerd/v2` and its `errdefs`/`log` split, `go.opentelemetry.io/otel…`, `gonum`). No dependency is introduced that `go.mod` does not name as indirect.

**Test: every leg is pinned to this plugin's own word.** Two tests compare `Invoke`'s reply against kit's own for the literal word `&quot;aur&quot;`: `TestInvokeResolvesThisBuilderWordsOwnStage` on `resolve`, and `TestInvokeServesThisBuilderWord` on `collect-context` and `reverse` (its reverse input carries every key a word's reverse reads, and the test refuses a context that yields no ops, so that leg cannot pass vacuously). A dispatch routed to another builder fails on all three — the defect a shared dispatch can introduce, and it was previously untested.

**This repo is a contract / library module** in the R10 sense: it ships no `box:`/`deploy:`/`check:` node, so no bed can exist here (proof below). Its class gate is its own Go suite. The live end-to-end proof is owed by the chain on opencharly/sdk#608 and runs when charly's leg of that chain drives this plugin over the real render path; this PR is `WAITING` on it and posts the matching `HOLDING` there.
